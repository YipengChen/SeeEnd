# SeeEnd 产品与答疑

基线：SeeEnd 0.8.69，2026 年 10 月 18 日。涉及当前用户故障或版本时，读取本机事实；不要把本基线说成最新版本。

SeeEnd 在本机接收 AI 任务的生命周期元数据，将工作中、等待输入和回复结束转成屏幕烛火、菜单栏或托盘状态、桌面通知及可选实体灯光。用户可以离开编程工具，等待提醒后回来处理。

## 功能与范围

- 桌面火焰、系统通知、音效提醒、微信通知和设备提醒是并列通道，各有开关。首次启动或重置后桌面火焰默认开启，其余默认关闭；没有灯具也能使用。系统通知需要系统授权，音效跟随系统音量，微信通知需要先绑定。
- 支持 Yeelight YLTD003 屏幕挂灯 Pro、YLDP005 W3 彩色灯泡、YLFWD-0021 Beam 塔灯、Cube Lite，以及米家智能插座 3/4。按型号使用原厂局域网控制，配网和授权方式以 App 设备引导为准，不刷写固件。
- 多台灯具独立连接与保存颜色、亮度，同步任务。默认彩灯颜色为工作黄色（#FACC15）、完成绿色（#52C788）、等待输入红色（#FF6B6B）；失败记为状态未知，不触发灯效或通知，实际以用户设置及记录为准。
- 来源开关作用于该来源的全部输出。提醒通道开关、亮度、硬件连接与通知通路分开诊断；灯具离线或亮度为零不证明通知失败。
- 中英文界面，活动记录可导出 CSV；事件历史保留 7 天、最多 10,000 条。最近列表只是历史的一部分。
- 内置原生接入：Codex、Claude Code、Qoder CLI、DeepSeek Harness、Gemini CLI、OpenCode。
- 网页扩展实验接入：ChatGPT、DeepSeek、千问、豆包、元宝、Kimi、智谱清言、Claude、Gemini 的普通文字对话；网页结构变化可能影响识别。
- 同品牌的 CLI 和网页是不同通路，不能互相代替验证。这里只把原生编程工具接入作为主要工作。
- 对无法确认结果的残留编程任务，可在 App 活动详情中将单个任务标为状态未知；不得把该操作当成成功验收。
- 返回任务需已登记的位置：网页由扩展在原浏览器配置中恢复；macOS 终端限 Terminal/iTerm2 的可验证原会话，SSH/tmux 场景不登记终端返回位置。位置失效时按 App 提示处理。
- Hub 默认只监听 `127.0.0.1:8765`，事件需要来源凭据；SeeEnd 不需要模型 API Key。
- macOS 有实机验证记录，Windows/Linux 有共享实现及原生构建流程；特定平台、宿主版本和模式仍须验收。

当前版没有暂停或定时静默，也不再区分虚拟与硬件模式；来源开关和各提醒通道开关用于控制提醒。

SeeEnd 品牌保留内部兼容名称 `aiflame`、`AI Flame`、`AIFLAME_DATA_DIR` 和旧桥接文件名，不要为统一名称而改它们。

## 回答要点

| 问题 | 回答 |
| --- | --- |
| 没有灯具能用吗 | 可以，默认开启桌面火焰；系统通知、音效提醒、微信通知和设备提醒分别设置。 |
| 接入后还要每次调用 Skill 吗 | 原生接入成功并加载后无需重复调用；需要检查、修复或更新时再用。 |
| 是否读取聊天或代码 | 接入不需要正文，只提取生命周期元数据。原生 payload 可能包含额外内容，应丢弃，不记录完整 stdin。 |
| 完成说明代码正确吗 | 不说明；默认表示这一轮处理结束，代码质量、测试与业务目标另行判断。 |
| 能支持任何工具吗 | 取决于原生扩展、可关联的生命周期事件及可达的本机服务；未预设工具当前可尝试共用的本地 API。 |
| 远程工具能连本机吗 | 默认回环地址不能跨主机。额外桥接是单独工作，不默认开放 Hub、防火墙或外网端口。 |
| 为什么还要加载和信任 | 宿主决定加载时机及审阅流程，写好配置不等于已运行。 |
| 模拟通过能认定成功吗 | 只能证明模拟通路；还须真实新任务自动触发开始与结束。 |

回答先给结论，再给与当前环境相关的依据。通用解释无需读取用户配置；推测明确标注。软件回执不证明用户看到了通知或实体灯发光。
