# 未预设工具的原生适配

先检查实际安装版是否已有新来源和接入方案；若有，使用已证实的内置能力，不受旧名单限制。

SeeEnd 0.8.69 没有动态来源注册。当前可行路线是用工具原生 Hook/插件创建薄适配，通过 `local-script` 上报。显示为“本地 API”，共用开关、凭据与验证范围，属于实验接入，不拥有独立工具身份或内置配置诊断。不能直接加 credentials.json 令牌、借用其他工具身份或修改 APP 注册表。

用户要求接入该工具时说明此范围；共用来源不满足用户需求时先确认取舍。没有可靠开始与最终结束关联能力时，明确缺口，不宣称完整接入。远程桥接与网络部署另行授权，不开放 Hub 解决。

## 创建要求

- 查对应宿主版本的官方扩展文档，列明开始、活动、等待、正常结束、取消、失败及缺失能力。
- 使用独立专用名称和目录，避免与内置插件或第三方同名。可用已确认运行数据目录中的 `agent-integrations/<tool-slug>/`，标明这是助手维护目录。
- 只提取会话、轮次和生命周期，禁止记录整个 stdin、正文或工具参数。缺少轮次 ID 时在原生开始回调生成并持久化，后续可靠关联。
- 使用本地进程按需读取既有 `tokens["local-script"]`；不输出令牌，不嵌入源码或配置，不自行生成替代凭据。
- 按 [protocol.md](protocol.md) 处理锁、序号、串行发送、租期、幂等、失败与中性 Hook 输出；用隔离桩测试取消、并发与长任务，不向正式 Hub 发模拟事件。
- 保存安装记录：适配版本、宿主与 APP 版本、协议、范围、事件映射、文件及校验值、配置条目标识、备份、时间和验证范围；不保存秘密或用户内容。
- `/api/integration-check` 不检查自建插件，使用独立静态检查和 App 真实任务证据验收，不能伪造内置归属标记。

## 数据路径基线

macOS：`~/Library/Application Support/AI Flame`；Windows：`%LOCALAPPDATA%/AI Flame`；Linux：`$XDG_DATA_HOME/ai-flame`，默认 `~/.local/share/ai-flame`。`AIFLAME_DATA_DIR` 可覆盖。以 App 实际目录为准，不能假定 Shell 的覆盖值等于 App 的值。

credentials.json 包含管理凭据和来源令牌，必须由本地程序读取，检查时不创建新凭据。自建适配也可通过其合法来源令牌使用 `/v1/status`，但完整管理检查使用本机会话。

验收按 [connect.md](connect.md) 建立新窗口，并用安装记录中的任务关联信息排除其他 local-script 事件。凭来源级 verified 无法独立证明本插件成功。
