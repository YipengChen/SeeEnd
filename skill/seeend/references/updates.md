# 协议与版本维护

分开记录 SeeEnd 应用、事件协议、宿主、适配和 Skill 版本。基线是 SeeEnd 0.8.69、管理契约 1、事件协议 1.0、Skill 1.0.6；App 版本或 URL 的 v1 不能推导事件 schema_version。

Skill 1.0.0 的 0.8.4 基线是历史记录，不应改写为当时已验证新接口。Skill 1.0.2 将当前基线更新到 0.8.55，识别返回任务的可选字段和已移除 error 的状态集合，并保留已知旧契约及历史 error 证据读取。当前客户端通过管理契约发现能力，仅保留已知旧响应格式的有限解析兼容；服务仍须通过 HMAC 双向鉴权，不能降级连接不支持 HMAC 的旧 App。新增字段或来源以实际契约为准。

Skill 1.0.5 对齐 SeeEnd 0.8.69 的 HMAC 双向管理鉴权：根 dashboard 密钥仅在本机使用，线路只发送随机挑战和绑定服务实例、配置代际及请求内容的短期签名；每次响应也需验签。不使用管理 Bearer 或 Cookie，不接受旧协议或匿名回退，重置后的旧代际请求不能获得新权限。缺失或无效凭据时停止，不修改配置或权限。管理契约仍为 1、事件协议仍为 1.0；支持旧响应格式不表示允许连接不支持 HMAC 的旧 App。

只检查更新时不升级。修复优先保持可用版本；用户明确升级某组件才改它，不顺带升级模型依赖、全局运行时或另一工具。

1. 核对当前版本、范围与已验证行为，读取实际 App 的 guide/check、可信发布说明或协议文档，并查匹配宿主版本的官方资料。
2. 区分路径、配置格式、事件、信任、插件 API、凭据、租期/来源策略或协议变化，依据具体差异迁移。
3. App 移动或助手更新：更新拥有的命令与桥接，重载并重新审阅信任，不改来源身份或任务语义。
4. 宿主事件变化：核对语义再修外层适配，继续只传最小元数据，不编辑 App 包内部文件。
5. 协议变化：取得可信规范，再核对字段、状态、鉴权、注册、幂等、时间、租期和终态。需要时读 [protocol.md](protocol.md)；没有可靠新规范就保留可用接入，报告缺口。
6. 用 `/api/integration-contract` 核对当前来源和只读证据能力；它不是动态注册或通用发送助手。未来新增注册/发送能力仅在接口与文档证实后使用。
7. local-script 迁移独立来源：核对新身份、停止双重上报，保留其他脚本及共享开关/历史，不复用旧任务 ID。
8. 保留可撤销旧文件，先静态或隔离验证，再切换、加载、信任并用真实新任务验收。超时先核对部分完成；失败撤销本次变更，不无限重试。
9. 更新适配维护记录及已验证范围。更新本 Skill 仅限用户要求或指定维护任务，不自动改安装副本或公开仓库。

参考版没有通用自动升级接口。升级 SeeEnd 本体用经过核实的完整发行包，保留用户数据；缺可信发布渠道就询问包或地址。需要关闭当前工作应用时遵循用户更新范围，不自行打断任务。

Skill 1.0.5 的管理响应上限与 App 客户端对齐为 32 MiB，以容纳多设备与较多活动记录的状态快照；仍逐响应验签并只输出白名单摘要，签名不符时停止。

Skill 1.0.6 与 App 0.8.69 一同迁入 SeeEnd 单仓库，采用 GPL-3.0-only；管理鉴权和协议保持兼容。
