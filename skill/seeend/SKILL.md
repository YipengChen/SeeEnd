# SeeEnd 接入与维护

SeeEnd 是本机 AI 任务提醒工具，以桌面火焰、托盘、系统通知、微信通知及可选实体设备提示任务状态。接入后由宿主原生事件和本地适配程序持续上报，无需每次使用本 Skill。参考基线为 SeeEnd 0.8.69 和事件协议 1.0，实际安装版优先。

## 执行流程

1. 识别用户要接入、检查、排查、答疑、修复还是更新。只检查、答疑或检查更新时不改配置；单独调用 Skill 且没有目标时默认只读检查。用户请求安装或修复，授权范围内的可撤销操作直接完成。
2. 确认当前宿主及入口、版本、实际运行主机、SeeEnd 版本和安装位置、配置目录或 Profile。模型名称不代表宿主；远程环境的回环地址不代表用户电脑。
3. 读取当前 App 的管理契约与接入方案，按实际能力使用其增量安装器及辅助进程命令。辅助脚本 [seeend_client.py](scripts/seeend_client.py) 默认只读并检查契约；旧响应格式兼容边界与 API 用法见 [api.md](references/api.md)。`--apply` 是脚本操作开关，不能替代用户授权。
4. 修改后检查文件，再按宿主规则加载和信任。无法从当前会话安全完成的重启或系统授权，交代具体下一步，不自行终止当前任务。
5. 安装、修复或更新后，用重载后的真实新任务验收；只检查时仅评估已有证据。同一新任务的开始与回复结束必须自动到达，且属于所选会话与范围；配置完成、助手退出码零、模拟或来源级历史成功均不足以证明本次接入。

## 接入边界

- 只修改所选宿主中归属明确的 SeeEnd 注册与专用适配文件。保留其他设置；写前备份，增量合并，幂等安装，撤销本次变更。不得修改 APP 源码或应用包内部文件。
- 保留用户禁用意图与组织策略，完成宿主要求的信任审阅，不绕过审批。不因修复接入顺带升级 APP、宿主或模型依赖。
- 不输出凭据、Cookie、完整环境或原生 payload，不读取会话正文。辅助客户端仅在本地读取当前用户私有 dashboard 凭据建立管理会话，不保存或修改凭据；原生接入只提取生命周期元数据。
- 不用规则文件要求模型自行上报，不手工向正式来源发送假任务来通过验收。不把取消、未知、工具调用结束或子代理结束映射为根任务成功。
- 参考版没有动态来源注册。新工具可用 `local-script` 实验接入，共用来源开关与验证范围；要说明这一限制，不能伪造独立身份或内置诊断支持。
- 安装超时可能已经部分完成，先检查再重试。缺少可靠信号、文档或执行权限时说明具体缺口；完成其他已授权工作，不假报成功。

简洁报告当前范围、实际版本、修改与备份、验证证据及剩余步骤。分别描述“配置就绪”“已加载或待信任”“收到开始”“真实新任务已验证”。说明覆盖了哪些场景，软件投递不能代替用户确认看到了横幅或灯光。
