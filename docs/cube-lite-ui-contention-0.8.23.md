# Cube Lite 在 SeeEnd 内试亮掉帧：共享锁竞争

> 版本记录：以下结论对应标题版本；当前能力及验证边界见 [产品基线](product/CURRENT_PRODUCT.md) 和 [验证入口](validation.md)。

用户观察独立脚本顺畅、正式程序试亮卡顿。

## 复现

正在运行的 0.8.22：/api/status 五次请求耗时 224–342 ms。界面每 1.5 秒请求一次完整状态，在与灯效线程共用的 Hub 锁内构建历史数据。用户数据库只读备份到内存分析，约 4900 条事件；一次 snapshot 约 251 ms，其中逐事件扫描全部回执占 176 ms。

使用内存副本、真实 Engine / DeviceOutput / YeelightTransport / 试亮流程，以本地假客户端记录发送时间，同时按界面频率持锁调用 snapshot：5 秒最大帧间隔 365.85 ms，轮询持锁约 261–264 ms。没有控制实体设备。

## 修改

- 完整快照先按事件分组回执，避免历史规模平方增长的扫描；同任务返回位置在本次快照中复用，下次刷新重新查询。
- 新增仅 dashboard 凭据可用的 /api/status/live，返回实时任务、设置与设备状态，省略历史构建。
- 设备页常规轮询使用轻量接口，保留已载入历史；明确刷新和页面切换仍加载完整快照。迟到的轻量响应不会覆盖离开设备页后的数据。
- 不降低 10 FPS，不放松发送前的状态复核，不删除历史记录。

同样的内存数据、正式发送线程和轮询频率测试：最大帧间隔 133.51 ms，中位数 99.98 ms，轻量轮询耗时 27.9–31.5 ms。该数据证明软件锁竞争得到缓解，不等同于实物显示帧率。

141 项核心/灯具测试通过；47 项原生界面、本地 HTTP 和任务返回测试通过，包含轻量轮询更新实时状态、历史保留及导航后补全。

## 仍未解决的独立问题

本轮开发期间，旧版运行程序再次出现 Cube 卡住。暂停重连后 UDP 会话与心跳仍得到确认，但 set_power off 超时；用户确认苹果家庭也控制不了。与上次故障表现一致。0.8.23 的性能修改不应被描述为修复该控制卡死，暂未验证长时间运行稳定性。
