# Cube Lite 局域网实机排查

> 版本记录：以下结论对应标题版本；当前能力及验证边界见 [产品基线](product/CURRENT_PRODUCT.md) 和 [验证入口](validation.md)。

2026-10-16，固件广播版本 1.0.0，型号 CubeLite；用户通过苹果家庭配网。

## 实测

- SSDP 可发现，support 字段为空；0.8.17 已修复发现过滤。
- TCP 55443 可连接，路由直接经 en0；本机没有发现其他连接占用该端口。
- get_prop 单属性、多属性均不返回任何字节；延长连接准备时间与读超时也无效。
- get_supported_fx_mode 和 get_fx_effect 同样没有回复。
- 对照设备 Beam 使用同样的 get_prop 请求立即返回状态。
- 同一 Cube TCP 连接内：set_bright 返回 ok；随后 get_prop 超时；再次 set_bright 返回 ok。
- set_power 返回 ok；activate_fx_mode 与 update_leds 组合发送成功，无异步错误。
- 用户确认看到了测试的五条青色竖线，随后变为偏青的白色。确认了真实点阵执行，但未确认白色校准准确。
- SSDP 中 bright 在亮度调整后仍报告 100，不能作为执行结果或实时状态的可靠回读。

## 结论与修复边界

当前固件不响应上述查询，不能据此认定局域网控制关闭。网络收发、可回执控制指令与点阵显示均已实测正常。尚不能证明固件内部为何忽略查询，也不能推断所有版本都一样。

首次接入与重连改为要求 set_bright 的真实 ok 回执，设置主亮度 100，与现有点阵渲染中按像素缩放亮度的方式一致。其他 Yeelight 型号继续使用 get_prop 验证；错误、超时或仅发送成功不能通过验证。

点阵发送仍标记 sent，不伪造帧确认或实时电源状态。此次不修改像素颜色校准，不依赖 Yeelight App，也不更改苹果家庭配对。
