# 总览硬件演示掉帧修正 0.8.24

> 版本记录：以下结论对应标题版本；当前能力及验证边界见 [产品基线](product/CURRENT_PRODUCT.md) 和 [验证入口](validation.md)。

用户确认设备单独试亮已流畅，总览演示仍卡顿。

0.8.23 的轻量轮询仅覆盖设备页。总览硬件演示将轮询周期设为 150 ms，却仍请求 /api/status，反复在动画线程共享锁内构建历史记录。

修改：总览存在 hardware_preview_id 时使用 /api/status/live（含显式 poll），保留已载入历史；演示结束后恢复普通完整刷新。迟到的轻量响应按请求时页面检查，离开页面后重新取完整数据。实时任务数、状态、连接与设置仍更新，不取消发送前状态检查，不调整 10 FPS。

7 项真实 Qt/HTTP 回归通过：轻量请求、阶段变化、演示到期恢复完整刷新、手动退出、设置切换、隐藏/导航，以及新真实任务到达时中断演示。测试使用隔离 Hub，无实体设备控制。

只读历史副本载入内存，以真实 Engine、DeviceOutput、YeelightTransport 和总览 preview 流程运行 5 秒，假客户端记录发送时刻，另线程每 150 ms 持锁轮询：

| 指标 | 完整轮询 | 轻量轮询 |
| --- | --- | --- |
| 发送间隔中位数 | 100.32 ms | 100.22 ms |
| 最长发送间隔 | 178.31 ms | 134.55 ms |
| 轮询耗时中位数 | 80.33 ms | 32.46 ms |

该结果属于软件路径复现，实物体感待更新后验证；此前控制卡死的根因仍未确认，本次不宣称修复卡死。
