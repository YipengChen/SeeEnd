# SeeEnd 软件需求文档

> 历史资料：保留原版本验收结果或设计调研，不代表当前支持范围。AI Flame 0.1 / 0.2 已于 2026-10-09 移除，旧实现见 [归档分支](https://github.com/YipengChen/SeeEnd/tree/archive/ai-flame-2026-10-09)。当前操作与支持设备以仓库 README 和使用指南为准。

## 1 产品定义与文档基线

SeeEnd 软件需求文档
文档版本：0.1 草案　｜　编制日期：2026 年 9 月 28 日
所属项目：设计所　｜　产品阶段：概念定义与 MVP 开发准备
适用读者：产品、桌面软件、浏览器扩展、嵌入式开发与测试人员。

SeeEnd 是通用桌面任务完成提示器，也是 AI 回复完成触发器。软件把多种来源的任务事件统一交给 Trigger Hub，再通过 USB 或 Wi-Fi 驱动 ESP32 火苗硬件，以柔和光效提示用户返回任务。本文用于确认产品边界、拆分开发工作和制定验收计划。

核心方案为 Trigger Hub + 多触发源 + 统一事件协议 + ESP32 火苗硬件。硬件只处理标准状态与显示参数；应用和网站差异集中在软件适配器中处理。无需购买指定大模型 API，也不要求用户更换日常使用的 AI 产品。

本文件中的 MUST 表示该版本必须实现，SHOULD 表示优先实现，MAY 表示可选。P0 是 V0.1 发布门槛，P1 是 V1.0 目标，P2 是探索项。全部性能数字均为拟定验收目标，并非已有实测结果；版本路线是建议基线，未代表已经开发或承诺发布日期。

关键边界
• “收到系统通知”不等于“任务成功完成”。只有命中明确完成规则的通知才能转为 done；普通通知默认忽略。
• 无通知、无可观察页面状态、无回调的第三方应用，不能承诺自动检测。兼容清单必须列出操作系统、应用或网站版本及测试条件。
• 本产品提示任务状态，不判断 AI 答案正确性、内容质量或业务结果。
• 外观、结构、光学设计及量产硬件认证另立规格；本文覆盖设备接口、固件状态与安全亮度约束。

阅读导航
第 2 章描述用户与目标；第 3 至 5 章描述架构、平台和触发；第 6 至 8 章定义协议、设备与隐私；第 9 至 12 章定义版本、质量、验收和扩展。

## 2 产品目标与核心使用场景

产品目标
G01：让用户离开生成或执行页面后，仍能获得低干扰、可辨识的完成反馈。
G02：以适配器扩展应用覆盖，保持硬件协议稳定；新增网站适配不应要求更换设备或固件。
G03：基础功能在本机运行，不以云账号、内容上传或订阅作为触发前提。
G04：用户能识别“未授权、来源不支持、设备离线、已匹配但未送达”等原因，避免无声失效。

目标用户
| 用户 | 主要任务 | 核心价值 |
| --- | --- | --- |
| 高频 AI 用户 | 等待长回复与多步任务 | 完成后返回，减少反复切换窗口 |
| 开发者与自动化用户 | 编译、测试、脚本、下载 | 用回调或 API 复用同一提示设备 |
| 创作与设计人员 | 渲染、导出、素材生成 | 长任务完成时获得桌面反馈 |
| 桌面设备爱好者 | 自定义场景和光效 | 可配置、可扩展且本地运行 |

核心场景
SC01 网页 AI 回复：用户在已支持网站提交任务，适配器观察到开始后发送 working；确认正常结束后发送 done；火苗持续约 10 秒后恢复默认显示。取消和断网不应触发完成光效。
SC02 桌面通知：用户授权通知访问并选择应用；新通知命中“完成”条件后点亮。该来源通常只能提供终态，不伪造 working。
SC03 开发任务：脚本结束时根据退出码调用本地 API；成功映射 done，失败映射 error。调用者负责提供真实结果。
SC04 暂时离开：用户设置夜间静默；静默期间仍记录事件元数据，但不点灯，静默结束不补播旧提示。
SC05 故障恢复：设备拔出后软件显示离线；重新插入恢复连接，仅发送仍有效的状态，不重播过期完成事件。
SC06 手机来源：V1.0 Android 经授权将匹配后的标准事件转给同网段 Hub，再驱动设备；电脑休眠时显示未送达，不承诺持续可用。

首启体验
安装 Hub → 连接设备 → 试亮 → 选择触发来源 → 按需授权 → 创建或启用规则 → 发送测试事件 → 查看结果。用户拒绝某项权限后，其余来源仍可使用。首次配置目标为 10 分钟内完成；以第 11 章用户测试口径验收。

## 3 系统架构与模块职责

逻辑数据流
通知监听／浏览器扩展／Webhook 与 API／Shortcuts／可选 Accessibility
→ 来源适配器 → Trigger Hub → 规则匹配与事件标准化
→ 去重与任务状态管理 → 设备路由与发送队列 → USB／Wi-Fi
→ ESP32 协议解析 → 本地火苗动画 → ACK 回执

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| 来源适配器 | 读取授权范围内的信号并附带来源标识 | 不直接控制灯效，不宣称未知任务成功 |
| Trigger Hub | 规则、任务状态、事件生命周期、设备调度 | 唯一桌面控制入口，默认本地运行 |
| 配置界面 | 配对、规则、静默、测试、状态与诊断 | UI 关闭后可驻留；彻底退出即停止采集 |
| 通信层 | 连接、鉴权、重试、ACK、重连 | 隔离 USB 与 Wi-Fi 差异 |
| ESP32 固件 | 校验命令、执行动画、亮度限幅、心跳 | 不接收聊天正文，不承担应用适配 |

AR01［P0］Hub 必须分离来源适配器、规则引擎、设备传输三个接口，并给每个适配器记录名称、版本、能力与健康状态。
AR02［P0］同一 Hub 的多个来源共用去重和路由。V0.1 支持单设备、单电脑控制；多电脑同时控制暂不支持。
AR03［P0］服务健康、来源健康、设备连接状态必须与任务状态分开呈现。设备离线不能被解释为任务 error。
AR04［P0］前台界面关闭后可选择继续驻留托盘或菜单栏；开机自启默认由用户选择。进程退出时明确告知触发停止。
AR05［P1］Android 作为来源端，默认只向已配对 Hub 发送标准事件。手机直连设备属于后续独立能力，避免两种架构混用。

部署建议
桌面可选跨平台 UI 配合平台原生模块；Windows 通知模块需验证应用清单、打包身份和权限流程。macOS 需验证签名、公证及 USB 权限体验。具体语言与框架在原型验证后确定，不能因跨平台框架选择而降低平台权限要求。

生命周期
来源没有完成信号时，Hub 仅显示来源不可用或任务状态未知；超过工作状态租期后撤销 working 展示。不得通过“等待足够久”生成 done。设备动画在固件本地运行，避免主机逐帧传输。

## 4 平台兼容策略

兼容性分为“计划支持”“实验适配”“未来探索”；本文件不将任何第三方 AI 应用标记为已验证。正式清单须包含平台版本、软件版本、来源类型、可用状态和验证日期。

| 平台 | 推荐路径 | 发布范围与限制 |
| --- | --- | --- |
| Windows | 通知监听、浏览器扩展、本地 API | V0.1；通知 API 需用户授权和清单能力声明 [S1] |
| macOS | 浏览器扩展、本地 API、Shortcuts | V0.1 扩展及 API；V1.0 快捷指令模板；不承诺通用通知抓取 |
| Chrome 与 Edge 桌面 | 指定站点内容脚本 + Native Messaging | V0.1；站点逐一适配，后台和休眠需实测 [S3][S4] |
| Android | NotificationListenerService → Hub | V1.0 目标；需通知访问授权，受系统和厂商后台限制 [S2] |
| iOS 与 iPadOS | 用户配置的 Shortcuts 或业务回调 | V1.0 提供指南；不是任意 App 通知监听器 [S5] |
| Safari 与 Firefox | 各自扩展和本机桥接适配 | P2；不因 Chrome 支持而自动视为兼容 |

Windows
UserNotificationListener 能读取获准访问的其他应用通知。实现须检查权限变化，记录基线并处理新增项；不能把安装前或启动时已有通知全部当作新任务。应用自身没有发出系统通知时，监听器不能补出完成信息。正式支持建议以 Windows 11 为主，Windows 10 仅列为待验证兼容项。[S1]

macOS
UNUserNotificationCenter 面向本应用及扩展的通知管理，不能据此承诺通用读取其他应用通知。优先支持网页适配与主动回调；Accessibility 仅作为用户显式开启的特定 App 实验适配，不读取通知数据库或依赖私有接口。[S6][S7]

iOS 边界与例外
普通配套 App 不应被设计为通用跨 App 通知抓取器。Shortcuts 仅能在系统支持的自动化条件或用户工作流中主动调用接口；没有“任意 AI 回复结束”的通用触发器。局域网接口要求 Hub 可达，部分动作的确认和后台表现须按版本测试。[S5][S6]

Apple ANCS 提供蓝牙低功耗配件获取多类 iOS 通知的专门路线；此外 Accessory Notifications 框架具有地区、资格与授权限制，官方当前说明包含欧盟条件。两者均需独立评估硬件、系统版本、准入和通知隐私，并不能证明 AI App 一定发送完成通知。列为 P2，不纳入 USB／Wi-Fi 首版承诺。[S8][S9]

版本冻结原则
V0.1 至少验证 Windows 11 x64、一个仍受支持的 macOS Apple Silicon 版本，以及两平台 Chrome 与 Edge 的冻结测试版本；V1.0 扩展 macOS Intel 与 Android 机型矩阵。最低系统版本、发行渠道和实际版本号在发布候选阶段填入兼容清单，未验证组合不得展示为支持。

## 5 触发来源与规则配置

FR01 通知监听［P0 Windows／P1 Android］
用户必须主动授权，默认应用白名单为空。按稳定应用 ID 或包名识别来源，显示名称仅用于展示。支持新增及更新通知，移除通知不触发 done；同一通知 ID 的更新必须去重。可选标题或正文关键词只在本地匹配，系统遮蔽的内容不得绕过。Android 的工作资料、敏感通知及省电限制纳入机型验证。[S1][S2]

FR02 浏览器扩展［P0］
扩展按站点申请权限，使用内容脚本观察页面状态；经 Native Messaging 交给本机桥接程序。仅允许安装时登记的扩展 ID 连接；站点脚本不能自行伪造扩展来源。每个适配器必须观察明确开始、结束及取消／错误条件，不能仅凭文本短暂停顿判定完成。[S3][S4]
默认首发候选为 ChatGPT 网页和 Claude 网页，立项原型需各验证一条完整流程；候选名称不代表已兼容。测试覆盖多标签、切换会话、刷新、后台标签、重新生成和流中断。适配失效时停用自动判定并显示原因；可提供手动测试按钮。第一方 hook 可用时优先使用，DOM 观察作为逐站点维护的实现。

FR03 Webhook 与本地 API［P0 本机／P1 局域网］
提供 POST /v1/events，默认仅监听回环地址，使用每安装实例生成的凭据。外部网络服务不能直接访问本机回环接口；公网上游接入需用户提供可信中继，托管云中继不在 MVP。V1.0 可主动启用局域网 HTTPS 接入，用于 Android 与 Shortcuts，需配对和独立令牌。

FR04 Accessibility 与 Shortcuts［P1／P2］
macOS Accessibility 按指定应用适配，显式说明权限用途，不执行点击或输入；必要 UI 元素不可访问时报告不支持。V1.0 仅提供一个实验适配原型，不作为正式全应用兼容能力。Shortcuts 模板可调用本机命令或已鉴权的 API；由调用工作流决定何时发送 done 或 error。[S5][S7]

FR05 规则配置［P0］
规则字段包括 rule_id、名称、启用状态、来源 ID、应用或域名白名单、匹配条件、目标状态、目标设备、优先级、冷却时间、光效和有效时段。V0.1 提供等于、包含、不包含与条件全满足；正则表达式列为 P1 并限制执行时间。
默认优先级 0，按优先级从高到低、同级按列表顺序处理；每个来源事件只执行第一条匹配规则。同一任务终态由高可信来源优先，显式回调高于已验证页面信号，高于通知文本推断。无任务关联键时不强行合并不同来源，UI 提醒用户同一任务选择主要来源，防止双响。

FR06 规则工具与示例［P0］
支持新建、复制、禁用、删除、导入导出、测试匹配和恢复默认；导出不含令牌、Wi-Fi 密码或通知正文。示例规则：指定应用 ID + 标题包含“任务已完成” → done，冷却 10 秒，显示 10 秒。它只是用户配置示例，不代表任何应用固定使用此文案。预览显示匹配原因；启用宽泛“任意通知”规则须明确说明可能误报。

## 6 统一事件协议与状态模型

EP01［P0］事件采用 UTF-8 JSON，schema_version 初始为 1.0。Hub 接入事件与设备显示命令分层：硬件仅接收 Hub 生成的状态、光效和不透明标识，不接收通知内容、提示词、回答或完整页面地址。

| 字段 | 必需 | 含义与约束 |
| --- | --- | --- |
| schema_version | 是 | 主版本不兼容即拒绝，兼容次版本可忽略扩展字段 |
| event_id | 是 | 全局唯一 UUID；重试保持不变 |
| source_id | 是 | 来源安装实例标识，凭据必须绑定此身份 |
| task_id | 是 | 来源内不透明任务标识；重生成使用新 ID |
| seq | 是 | 同任务递增整数；拒绝旧序号覆盖新状态 |
| state | 是 | idle、working、done、error 四选一 |
| occurred_at | 是 | RFC 3339 UTC 时间，保留原始发生时间 |
| ttl_ms | 是 | 接收有效期 1000 至 300000 毫秒，默认 60000 |
| device_id | 否 | 缺省交给路由规则；未知目标报错 |
| reason | 否 | 枚举，如 completed、failed、cancelled、timeout |

外部调用示例
```json
{
  "schema_version": "1.0",
  "event_id": "5df904bb-8272-4367-8d0a-a13ae4aa9cd0",
  "source_id": "local-script-01",
  "task_id": "build-20260928-001",
  "seq": 2,
  "state": "done",
  "occurred_at": "2026-09-28T12:00:00Z",
  "ttl_ms": 60000,
  "reason": "completed"
}
```

状态语义
idle：没有活动任务，默认熄灭，可选极弱待机光。working：已观察到任务执行，低亮呼吸。done：有明确成功结束信号，暖色火苗默认 10 秒，可设 3 至 60 秒。error：明确失败信号，以可配置节奏提示默认 10 秒；不依赖颜色作为唯一差异。

EP02［P0］允许 idle → working → done／error；通知型来源允许直接 done／error。用户取消映射 idle + cancelled，停止完成提示。任务终态不可被迟到的 working 覆盖；新一轮执行须建立新 task_id。无信号的超时只撤销 working 并在软件标记未知，不生成成功结果。
EP03［P0］working 租期默认 120 秒，可由来源每 30 秒续期；无法续期的适配器应只发终态。设备显示与任务记录分离：提示结束后，若仍有活动任务则回 working，否则回 idle。
EP04［P0］同一 event_id 在 24 小时内至多处理一次；持久化最小去重索引。来源键 source_id + task_id + seq 防止乱序和重复。通知适配器用系统通知 ID 与修订内容的本地摘要映射事件。
EP05［P0］并行任务分别记账。error 提示优先于 done，终态提示优先于 working；同级按到达顺序。每设备最多保留 20 条未过期提示，满队列先淘汰最旧低优先级项并计数；静默时不排队补播。

## 7 设备通信与灯效控制

DV01 USB［P0］
V0.1 使用 ESP32-S3 参考板或带兼容 USB 串口桥的 ESP32 板，最终型号由硬件验证冻结。USB 提供供电与串口数据，协议为换行分隔 JSON；单帧上限 4 KiB，解析超时 2 秒。坏帧隔离，不执行未通过校验的命令。按设备唯一 ID 重连，不依赖易变串口名称。
首次连接交换 hello、device_id、firmware_version、protocol_version、capabilities；不兼容时禁止控制并显示升级说明。物理 USB 首次连接由用户选定设备并确认，设备只接受当前控制会话命令。

DV02 命令与回执［P0］
显示命令字段：command_id、session_id、seq、state、effect、brightness、duration_ms、lease_ms。brightness 为 0 至 100 的用户百分比，由固件转换并受硬件最大电流约束。duration_ms 控制提示持续时长，lease_ms 控制有效显示租期，不能混用。
设备完成校验并安排动画后回复 applied ACK，包含 command_id 和结果；非法字段返回 rejected 及错误码。ACK 表明固件接受并执行调度，不证明 LED 的物理发光正常。软件应区分 received、matched、queued、applied、failed 和 suppressed。
2 秒未收到 ACK 时最多重试 3 次，间隔 0.5／1／2 秒且复用 command_id。设备对重复命令回同一结果，不重复启动提示；重启生成新 session_id，Hub 重连后只同步有效显示状态。传输采用至少一次投递和幂等执行，不宣称网络层严格恰好一次。

DV03 Wi-Fi［P1］
同一局域网使用 HTTPS／WSS 与设备建立鉴权会话；USB 辅助配置网络、设备身份与证书指纹，首次物理确认后绑定。mDNS 用于发现，允许手动地址，不作为信任依据；不得对局域网提供无鉴权控制接口。首版 Wi-Fi 不支持公网端口映射、校园企业认证网或云依赖。
USB 与 Wi-Fi 同时可用时按设备 ID 合并，优先 USB，只有失败后才切换；切换保留命令去重信息。一台设备只接受一个已配对 Hub 的活动控制会话；转移控制需用户操作。

DV04 故障与安全显示［P0］
心跳建议每 5 秒，连续 3 次失败显示离线。控制通道丢失后固件 30 秒内渐暗至 idle，不能永久维持 working。断电恢复默认熄灭；任何恢复都不自动重播旧完成提示。
本地动画至少以 30 Hz 更新，亮度渐变、不采用默认高频爆闪。提供全局亮度、夜间静默、降低动态效果和立即熄灭；error 可用节奏区分。温升、电源预算、LED 峰值电流上限必须由硬件样机验证后写入固件配置，未验证前不开放无限亮度或用户代码动画。

DV05 维护［P0／P1］
V0.1 提供 USB 固件升级与失败恢复说明；V1.0 才引入签名升级包、校验和回滚。界面显示固件及协议版本，升级失败后不得出现持续高亮。

## 8 本地隐私与用户界面

PR01 数据最小化［P0］
默认不上传聊天内容、通知正文、访问页面或用户行为；核心匹配和去重在本地完成。规则需要通知文本时仅在内存中处理，处理后释放；日志不持久保存全文。设备接收不透明任务 ID 及灯效参数，不接收应用正文。通知内容不得用于执行脚本或拼接命令。

PR02 权限控制［P0］
按来源解释用途并按需授权。通知权限拒绝或撤销后停止该来源；Accessibility 默认关闭；扩展仅请求支持站点的最小权限，隐私模式默认不启用。停止监听、暂停全部触发与删除本地数据应在设置中可直接找到。

PR03 本地存储［P0］
保存规则、设备 ID、设置和必要去重元数据。API 令牌存入操作系统凭据库，配置导出排除秘密字段。事件日志默认保存 7 天或 10,000 条，先到上限即轮换；只记录时间、来源别名、规则 ID、状态、结果与错误码。用户可关闭历史并一键清除；清除会同时重置去重记录，应告知可能重新处理上游重发事件。
临时诊断模式需主动开启并在 15 分钟后自动关闭，仍默认脱敏；导出诊断前允许预览，排除令牌、SSID、完整 URL 和内容正文。崩溃报告与遥测默认关闭，离线模式不检查更新。

PR04 接口安全［P0／P1］
本地 API 必须鉴权，令牌可撤销及轮换；校验 Host 与 Origin，拒绝未授权浏览器跨源请求，不依赖 CORS 代替鉴权。输入限制 4 KiB、单来源 10 请求／秒、突发 20；超限返回 429。局域网接入采用独立凭据和 TLS，校验配对身份；错误凭据、过期事件和重放不得触发设备。公网接入不包含在默认配置中。

UX01 主要界面［P0］
首页显示设备在线情况、最近一次触发结果、当前活动任务数量、来源健康与暂停开关。来源页显示权限和兼容状态。规则页提供模板、条件、目标、光效与测试。设备页提供试亮、亮度、连接方式、版本和解绑。诊断页用一条事件链说明“收到 → 匹配 → 发送 → 设备确认”。

UX02 可理解的失败反馈［P0］
分别展示“没有收到来源事件”“规则未匹配”“被静默抑制”“设备离线”“设备拒绝命令”。禁止在只收到 API 请求时就显示“火苗已点亮”。错误提示给出可执行下一步，如重新授权、连接设备或停用失效适配器。

UX03 配置保存［P0］
规则变更先校验再原子保存，失败保留上一版本；导入先预览差异，未知字段提示兼容情况。删除设备不自动删除规则，应标记目标失效并要求重新选择。支持中文界面、键盘操作和系统缩放；光效状态同时在软件以文字显示。

## 10 非功能需求与风险控制

所有数值在本章定义为工程目标。基准环境为至少 4 核 CPU、8 GB 内存桌面电脑，单 Hub、单 ESP32 设备、50 条规则、10 个并发任务；浏览器最多 5 个受支持标签。具体机器、系统与固件版本需随测试结果记录。

| 编号 | 指标 | 验收目标与口径 |
| --- | --- | --- |
| NFR01 | 软件处理时延 | Hub 收到有效事件至发出命令 P95 ≤ 200 ms，1,000 次 |
| NFR02 | 实体反馈时延 | Hub 收到事件至 LED 开始变化 USB P95 ≤ 500 ms；Wi-Fi ≤ 1 s，1,000 次 |
| NFR03 | 可靠性 | 正常在线受控测试 1,000 次有效事件，成功率 ≥ 99.5%，重复提示为 0 |
| NFR04 | 资源占用 | Hub 空闲 CPU 60 分钟均值 < 1%，私有内存 ≤ 200 MB；不计浏览器进程 |
| NFR05 | 长时稳定 | 72 小时运行无崩溃；预热后内存增幅 ≤ 20%；注入 100 次断连可恢复 |
| NFR06 | 恢复能力 | USB 再连接 10 秒内恢复；Wi-Fi 网络可用后 30 秒内恢复，不补播过期事件 |
| NFR07 | 可维护性 | 适配器故障隔离；规则迁移失败保留原件；协议主版本不兼容明确拒绝 |
| NFR08 | 隐私与安全 | 默认零内容出站；鉴权、权限撤销、脱敏、重放用例全部通过 |

NFR02 的测量应使用同步日志结合视频或光电传感器观察物理 LED 起亮；不能以 ACK 代替物理结果。平台发通知的延迟、页面回调延迟另记，不算入设备链路时延，但须在端到端场景测试中披露。

| 风险 | 影响 | 应对与发布边界 |
| --- | --- | --- |
| 应用不发通知或前台不通知 | 漏报 | 提供其他来源，按场景列兼容，不宣传全应用 |
| 页面 DOM 或文案改变 | 误判与失效 | 版本化适配、回归样本、异常停用、显式降级 |
| 取消、网络中断或暂停被当完成 | 假成功 | 分开终态信号，负例测试，未知不映射 done |
| 多来源重复与多任务乱序 | 双响或状态倒退 | 来源关联键、seq、幂等与单来源默认策略 |
| 系统休眠与后台限制 | 延迟或漏报 | 展示前提、恢复后丢弃过期事件、不承诺离线检测 |
| Wi-Fi 隔离和证书问题 | 设备不可达 | USB 后备、手动发现、诊断、不降低鉴权 |
| 安装包或扩展上架限制 | 发行受阻 | 提前验证签名、公证、权限说明及商店要求 |
| 通知文本与令牌泄露 | 用户隐私损害 | 内存匹配、脱敏、凭据库、最小权限与导出审查 |

商业化限制
售卖页面需按已实测来源列出支持能力、需要安装的软件和权限，以及睡眠、断网与无通知时的表现。物理产品的电气安全、无线合规和认证属于独立上市工作，不因软件验收通过而自动完成。

API 接收与设备送达分开验收
POST /v1/events 成功入队返回 HTTP 202 与 event_id，不表示设备已经执行；重复事件返回 200 与 duplicate=true。GET /v1/events/{event_id} 返回当前处理结果，受同一来源权限限制。离线事件可在 TTL 内等待，过期标记 expired；TTL 外输入返回 422。发生时间允许未来偏差 30 秒，超出拒绝并提示校时，后续等待用单调时钟计时。
