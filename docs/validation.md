# SeeEnd 验证说明

当前文档和源码基线为 App **0.8.56**、扩展 **0.2.13**。本页说明如何验证及如何解释结果，不将旧版测试数量、截图或硬件记录视为本版已全部复验。当前操作见[使用指南](quick-start.md)，实现范围见[产品基线](product/CURRENT_PRODUCT.md)。

## 证据层级

| 证据 | 能证明什么 | 仍需确认什么 |
| --- | --- | --- |
| 源码检查、配置检查 | 已实现的路径、当前配置及静态约束 | 宿主实际加载、权限、真实任务 |
| 自动回归、模拟协议、隔离截图 | 覆盖用例中的生命周期、接口、布局及异常处理 | 真实账号、工具版本、系统行为和物理设备 |
| 同一新任务收到开始与完成 | 该来源在本次场景的生命周期链路 | 其他模型／模式、后台、取消、并发等场景 |
| 通知或设备协议已接受 | 本次请求已提交或协议回执成功 | 系统横幅、手机收件、真实灯光 |
| 实际用户／设备观察 | 明确版本、平台和场景中的最终表现 | 未测版本、设备、账号和其他平台 |

记录取消、未知或超时不能当成任务成功；灯效演示和手动模拟不计入真实接入验证。`sent`、`applied`、「本地状态已更新」等字段应按各通道语义解释，不能直接当作物理效果确认。

## 自动检查入口

安装与环境要求见 [README](../README.md#开发测试与构建)。先跑改动涉及的定向用例，再按范围运行完整回归：

```sh
python -m unittest discover -s tests -v
npm ci --ignore-scripts
npm test
```

无显示器可设置 `QT_QPA_PLATFORM=offscreen`。Qt 测试、真实 Cocoa 测试、回环端口／IPC 测试和冻结 Helper 测试分别依赖对应环境；报告须保留通过、失败和跳过原因。权限受限导致未执行的用例不得记为通过。

`tests/render_desktop.py` 提供隔离渲染夹具。界面检查覆盖当前中英文、宽窄窗口及重要错误／等待状态；离屏截图不能替代原生窗口、系统权限和辅助功能实测。常规自动回归不使用个人配置，不向真实账号发送付费请求，不控制真实灯具。

## 构建与冻结验证

在目标操作系统依次执行：

```sh
python packaging/build.py --download-sources
python packaging/verify_frozen.py
python packaging/archive.py
```

已有校验通过的第三方材料可省略下载选项；独立输出目录需在三个命令中一致传入 `--dist-dir`。核心变更可先运行 `python packaging/verify_native.py`，或构建时使用 `--verify-native`。

核对 App 版本、扩展资源、`SeeEnd-build.json` 的源码身份、辅助进程生命周期、原生模块与分发包完整性。源码或资源变化后重新构建，不用重命名替代构建。冻结测试在本机权限受限时可能明确报告部分 HTTP／IPC 场景未验证；应单独保留该边界，CI 的完整性要求仍按构建脚本执行。

构建成功、签名静态校验通过、生成归档、公开仓库上传、扩展商店审核和各平台实际安装是不同结果，应分别记录。

## 真实场景验收

`tests/verify_*_live.py` 等工具用于手动实机检查，运行前阅读参数、目标和可能产生的真实操作。验收记录至少包含日期、App／扩展／宿主版本、平台、任务标识或脱敏证据、实际观察及未覆盖范围。

- **编程工具**：验证选定会话的新主回复开始与完成；按实际用法补充等待输入、恢复、中断、长任务、并发与重启。不同 DeepSeek Profile 和宿主版本分别记录。
- **网页**：逐站、逐账号／模式核对新任务、主动停止、切后台和多标签情况。重载扩展后刷新网页，不用历史结构测试推断新版网站可用。
- **任务返回**：分别核对网页原配置、关闭／导航后恢复，Terminal／iTerm2 授权、分屏、进程退出和歧义拒绝；生命周期通过不代表返回通过。
- **通知**：系统权限和专注模式、主窗口隐藏、微信本人扫码与手机收件分别观察。接口接受和桌面 claim／ack 不是展示证明。
- **设备**：按型号确认发现、身份、试亮、各状态、参数变更、重连、待机与退出后的实际灯光／通断电；Beam／Cube 的帧发送不能替代肉眼观察。Windows DPAPI 与其他平台需在原生系统验收。
